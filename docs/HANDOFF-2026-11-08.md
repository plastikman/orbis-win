## What was done (2026-11-06 → 11-08)

### GPU memory (v0.0.1, 01.41)
- **The bug:** Fallout 3 crashed opening the Pip-Boy, New Vegas in V.A.T.S., and L4D2 after 3.5 min.
  - **Cause:** freed GPU address ranges were never handed back under continuous rendering. `orbis_retire_ranges` released a range only when the GPU had caught up with every submission, which deferred present never allows.
- **The fix**, in the PS4 RADV layer (`ac_orbis_drm.c`, `wsi_orbis.c`):
  - **Per-frame retire:** `ac_orbis_frame_boundary()` from the WSI present.
  - **A 1 GiB window extension**, with direct memory committed on demand (`ORBIS_ARENA_EXT_MIB`, default 1024).
  - **Honest heap sizes**, split 1/3 GTT and 2/3 VRAM, with usage counted once.
- **Where it lives:** Mesa patches `0041` (resync) and `0042` (the fix), commit `95f1e75`.
- **Patch series status:** the series rebuilds the shipped driver:
  - 0001–0040 apply with `patch -p1 --forward`. 0010 loses one hunk, which 0041 covers.
  - 0041 and 0042 apply with `git apply`.
- **Profiles can now set the driver's own options** (`[debug] env = ORBIS_...`), prospero-win `2e7f76a`.
- **Full run on 01.41 passed.**
  - GTA IV, FNV, FO3, Oblivion, MDK (translator), Half-Life, Bloodlines, Titan Quest, Half-Life 2, Space Cadet Pinball.
  - Plus L4D2 for 7 m 45 s.

  - A new `dlls/quartz/mpegaudiosplit.c`.
  - `l3codecx` hosts `mp3dmod` through the DMO Wrapper.
- **Packaging:** the package takes these DLLs from `<ABI4>/source/.deps/wine-host/install/usr/lib/wine/`, not from `build/wine-ps5/pe`.
- **Hardware results:**
